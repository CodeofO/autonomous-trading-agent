# 설계 결정 기록

형식: 결정 / 이유 / 영향. 날짜는 모두 2026-11-02.

### D-01 실계좌(live) 주문 코드 경로를 만들지 않는다
- `Settings.trading_mode` 는 `Literal["paper"]` 이고, 다른 값은 검증 단계에서 기동을 거부합니다. `run.sh` 도 미리 확인합니다.
- `BrokerInterface` 의 구현은 `PaperBroker` 하나뿐입니다. 모든 구현이 `is_paper=True` 인지 테스트로 강제합니다(`test_no_live_broker_implementation_exists`).
- 이유: '기본 비활성 + 다중 가드'보다 '경로 없음'이 더 안전하고 검증하기 쉽습니다.

### D-02 외부 호출 허용목록 + 증권사 호스트 차단목록
- `core/http.SafeHttpClient` 만 외부로 나갑니다. (호스트, 메서드, 경로) 허용목록 밖이면 `OutboundBlockedError` 를 던집니다.
- 증권사 API 호스트(토스·한투 실전/모의·키움·LS·Alpaca)와 주문형 경로(`/orders`, `/trading` …)는 `LiveOrderBlockedError` 로 막습니다.
- 차단은 네트워크 전송 전에 일어납니다(respx 로 "호출되지 않음"을 검증).

### D-03 방향 전환: 토스증권 → 국내 주식 + 자체 모의계좌 → (재전환) 토스 시세 + 자체 모의계좌
- 토스증권 Open API 공식 문서(OpenAPI 1.2.28)를 조사했습니다. 서버가 `https://openapi.tossinvest.com` 하나뿐이고 모의투자·샌드박스 언급이 없습니다.
- 사용자가 "쉬운 모의투자 플랫폼 또는 자체 구현"을 요청했고, 선택지 중 **국내 + 자체 모의계좌**를 골랐습니다.
- 토스 조사 결과는 `docs/archive/` 에 보관했습니다.

### D-04 데이터 소스는 공식 API 만 쓴다 (D-23·D-28 로 대체: 시세는 토스증권)
- 시세: 공공데이터포털 금융위원회_주식시세정보. 재무·공시: OpenDART. 뉴스: 네이버 검색 API.
- pykrx·FinanceDataReader 등 비공식 스크래핑 라이브러리는 쓰지 않습니다(출처 불분명·약관 위험).
- 제약: 시세가 **T+1 일봉**뿐입니다. 장중 실시간 시세는 증권사 계좌가 있어야 받을 수 있습니다.

### D-05 체결 규칙: '다음 공식 가격' (D-24 로 대체: 운영은 실시간 체결. 백테스트에만 이 규칙 사용)
- 08:30~09:00 접수 → 당일 시가, 09:00~15:20 접수 → 당일 종가. 그 외 시간과 휴장일은 거부합니다(장 운영시간 외 주문 금지).
- 체결은 다음 영업일 13시 이후, 해당 일봉이 공개되면 확정됩니다. 미래 가격을 쓰지 않으면서 판단과 체결을 하루 안에 맞추기 위한 규칙입니다.
- 종가 단일가(15:20~15:30)와 시간외는 단순화를 위해 제외했습니다.

### D-06 판단 주기는 하루 2회 (사용자 선택) (D-29 로 대체: 1시간 간격)
- 08:35 오전 세션, 14:00 오후 세션. 13:20에 일봉 동기화와 체결 확정, 15:45에 리포트.
- 원 스펙의 '장중 1분 주기 전략 실행'은 일봉 데이터 제약 때문에, 데이터 공개 시점의 손절·익절 감시와 하루 2회 판단으로 대체했습니다.

### D-07 실시간 = 백엔드→UI WebSocket
- 외부 실시간 시세 구독은 없습니다(D-04). WebSocket 은 채팅·감사로그·상태 이벤트 전달에 씁니다.
- 브라우저 WebSocket 은 헤더를 못 붙이므로 쿼리 토큰을 씁니다. 대신 접근 로그에서 `token=` 을 마스킹합니다.

### D-08 LLM: OpenAI 호환 Chat Completions, SDK 없이 httpx
- 사용자가 `.env` 에 base URL·모델·키를 넣는 방식을 요청했습니다. 이 세 값으로 붙는 사실상의 표준이 OpenAI 호환 API 입니다.
- tool calling 으로 리서치 루프를 돌리고, 미지원 제공자는 자동으로 JSON 모드(자료 일괄 전달)로 전환합니다.
- SDK 를 쓰지 않아 의존성이 줄고, 허용목록 HTTP 클라이언트를 그대로 통과합니다.

### D-09 Mock 시장은 가상 종목 20개 (D-28 로 폐지)
- 실존 기업명을 쓰면 LLM 이 사전지식으로 판단해 가상 데이터와 어긋납니다. 그래서 `MOCK01 가온전자` 같은 가상 기업을 씁니다.
- 이벤트(호재·악재)를 뉴스·공시로 먼저 내보내고, 이후 며칠간 가격 drift 에 반영합니다. 리서치가 의미 있도록 만든 장치입니다.
- 날짜별 독립 RNG 로 결정적으로 생성합니다(재시작·구간 분할과 무관하게 같은 데이터).

### D-10 LLM 이 없으면 규칙 기반 에이전트
- 같은 도구·같은 결정 형식을 씁니다. 뉴스 키워드, MA 크로스·RSI 신호, 20일 모멘텀, PER 을 단순 합산합니다.
- 키가 없어도 전체 시스템이 끝까지 돌아가게 하기 위한 장치입니다(예시이며 투자 권유가 아님).

### D-11 리스크는 코드가 강제하고, LLM 은 '의도'만 낸다
- 모든 주문은 `OrderManager.submit → RiskManager.check` 를 반드시 통과합니다.
- 수량이 한도를 넘으면 한도까지 **축소**(채팅에 안내)하고, 0이 되면 차단합니다.
- 매수 사이징: 기준가 × 1.05(시가 갭 여유)로 계산합니다.
- 보유 종목을 언급하지 않은 결정은 시스템이 HOLD 로 기록합니다(보유 종목 처리 누락 방지).

### D-12 인증: 기본은 로그인 없음, 선택적으로 scrypt 해시 + HMAC 서명 토큰
- (2026-11-02 변경) 사용자 요청으로 **로그인을 기본으로 끕니다**(`AUTH_ENABLED=false`). 서버는 `127.0.0.1` 에만 바인딩돼 이 컴퓨터에서만 접속할 수 있습니다.
- 다른 사람이 접근할 수 있는 환경에서는 `AUTH_ENABLED=true` 로 켭니다. 그러면 아래 방식의 로컬 계정 로그인이 동작합니다.
- 로컬 단일 사용자 용도라 외부 라이브러리 없이 표준 라이브러리로 구현했습니다.
- 서명 키는 `APP_SECRET_KEY` 또는 `data/.secret_key`(권한 600, 자동 생성)를 씁니다.
- 첫 접속 시 UI 에서 계정을 만듭니다. 비밀번호는 `.env` 에 두지 않습니다.

### D-13 DB: 로컬 SQLite, Docker PostgreSQL, Alembic 자동 업그레이드
- 앱 기동 시 `alembic upgrade head` 를 실행해, 어떤 실행 방식이든 스키마가 맞습니다.
- compose 의 PostgreSQL 비밀번호는 로컬 전용 기본값입니다(포트 미노출). `POSTGRES_PASSWORD` 로 바꿀 수 있습니다.

### D-14 시각은 항상 UTC 로 저장 (`UTCDateTime`)
- SQLite 가 시간대를 버려서 KST 시각이 9시간 어긋나는 문제를 실행 중 발견했습니다. 이 문제는 최소 주문 간격 계산에도 영향을 줍니다.
- TypeDecorator 로 저장 시 UTC 변환, 조회 시 aware UTC 반환으로 통일했습니다(회귀 테스트 포함).

### D-15 백테스트는 규칙 전략만, 시점별 공개 데이터만
- LLM 은 학습 데이터로 과거의 '미래'를 알 수 있어 백테스트 결과가 왜곡됩니다. 그래서 LLM 판단은 백테스트하지 않습니다.
- 백테스터는 운영과 같은 PaperBroker·RiskManager·OrderManager 를 씁니다. 일봉은 공개 시점에 맞춰 순차 적재합니다.

### D-16 프론트 의존성 버전
- 검증된 메이저로 고정했습니다: React 19.1, Vite 6.3, Vitest 3.1, TS 5.8, TanStack Query 5, lightweight-charts 5.0.
- Playwright 는 1.52 가 Node 25 에서 설정 로딩 중 멈춰서 1.64.1(2026-10-14 배포)로 올렸습니다.
- 차트는 한국 관례대로 상승을 빨강, 하락을 파랑으로 표시합니다.

### D-17 프롬프트 인젝션 대비

### D-22 재빌드 시 이전 이미지 정리
- 사용자 요청으로 `run.sh up`/`docker` 가 빌드 전후의 이미지 ID 를 비교합니다. 이번 빌드로 대체된 이 프로젝트의 backend·frontend 이미지만 지웁니다.
- 베이스 이미지(python·node·nginx·postgres), 다른 프로젝트 이미지, 빌드 캐시는 지우지 않습니다. 빌드 캐시는 다른 프로젝트와 공유돼 함부로 지우면 안 됩니다.

### D-23 토스증권 시세 재채택 (조회 전용) + 가드 재설계
- 사용자 결정(2026-11-02): 향후 토스 실거래를 염두에 두고 지금부터 토스 API 로 실제 종목을 다룹니다.
- 사용 범위는 조회 7개 경로뿐입니다: 토큰, 현재가, 캔들, 종목, 전체 종목, 랭킹, 장 운영 캘린더.
- 재무제표·뉴스는 토스 API 에 없어 DART·네이버를 계속 씁니다.
- 가드 순서를 바꿨습니다.
  1. 주문·계좌 경로는 어떤 호스트든 허용목록보다 먼저 차단합니다.
  2. 허용목록에 정확히 일치하는 조회 경로만 통과합니다.
  3. 그 밖의 증권사 호스트 경로는 차단합니다.
- 토큰은 메모리에만 두고(클라이언트당 1개 유효) 만료 60초 전 또는 401(`expired-token`/`invalid-token`/`token-revoked`) 수신 시 1회 재발급합니다.
- 호출 한도는 그룹별 토큰 버킷으로 공식 한도의 80% 를 씁니다.

### D-24 실시간 모의 체결 (토스 모드)
- 장중 시장가는 현재가 ± 슬리피지로 즉시 체결합니다. 지정가는 가격 도달 시 체결합니다.
- 장전(08:30~09:00) 주문은 09:00 이후 첫 현재가로 체결하고, 15:20 까지 미체결분은 당일 만료로 취소합니다.
- 장중 1분 주기로 체결 확인과 손절·익절을 감시합니다(원 스펙의 '장중 1분 주기' 복원).
- 거래량 참여율 상한은 실시간 모드에 적용하지 않습니다(호가 잔량 데이터 미사용). 큰 주문의 체결가가 낙관적일 수 있습니다.

### D-25 데이터 소스가 바뀌면 모의계좌 새로 시작
- 가상 종목 포지션은 실제 시세로 평가할 수 없으므로, 소스가 바뀌면 다음을 초기화합니다: 현금·포지션, 미체결 주문 취소, 자산곡선, `MOCK*` 관심종목.
- 주문·체결·결정·감사 기록은 보존합니다.

### D-26 실거래 주문 경로는 만들지 않음 (향후 별도 작업)
- 토스 주문 API 어댑터는 이번 범위에서 구현하지 않습니다. 실제 돈이 움직이는 코드는 사람이 검토하고 소액으로 시험한 뒤 붙여야 합니다.
- `BrokerInterface`(place/cancel/status/positions/balance)가 그 자리를 준비해 둡니다.
- 붙일 때 필요한 것: 다중 가드(환경변수 + 설정 + UI 이중 확인), 가드 테스트 수정에 대한 명시적 승인, `X-Tossinvest-Account` 계좌 헤더, `clientOrderId` 멱등키 연동.

### D-27 트레이딩 룸에서 규칙 기반 시절 메시지 삭제
- 사용자 요청으로 LLM 연결 전 규칙 기반 세션의 채팅을 지웠습니다. 대상은 해당 세션 메시지와 그 시기의 시스템·체결봇·리스크봇 메시지입니다.
- 주문·결정·감사 기록은 남깁니다.

### D-28 목업 전면 제거 — 실제 종목·실제 시각만
- 사용자 요청(2026-11-02)으로 다음을 앱 코드에서 삭제했습니다: `MockWorld`(가상 종목), 공공데이터 일봉 경로, 가속 시뮬레이션 시계·배속 API·UI, `DATA_SOURCE`·`CLOCK_MODE`·`SIM_*` 설정.

### D-34 토스증권 실거래 모드 추가 (사용자 결정)
- 사용자가 실거래 기능 구현을 요청했습니다. 켤지 말지는 사용자가 정합니다. 기본은 계속 모의투자입니다.
- 켜는 방법: `.env` 에 `TRADING_MODE=live` 와 `LIVE_TRADING_CONFIRM=I_UNDERSTAND_REAL_MONEY` 를 함께 넣습니다. 확인 문구가 없으면 기동이 거부됩니다(`Settings`, `run.sh` 이중 확인).
- 구현은 토스 공식 OpenAPI 명세(1.2.28)의 주문·계좌 스키마만 따릅니다(`docs/TOSS_API_NOTES.md` §5).
  - `TossTradingClient`: 계좌·잔고·주문가능금액·주문 생성·취소·조회만 허용목록에 둡니다. 정정·조건주문은 호출하지 않습니다.
  - 주문·계좌 경로는 이 클라이언트(`allow_trading=True`)에서만 나갈 수 있습니다. 모의투자 모드에는 이 클라이언트가 아예 만들어지지 않고, 다른 클라이언트에서는 여전히 항상 차단됩니다.
  - 토큰은 클라이언트당 1개만 유효하므로 시세 클라이언트의 토큰을 같이 씁니다.
- 실거래 전용 안전장치(리스크 한도·킬 스위치는 모의투자와 같이 적용):
  - 하루 매수 총액 상한 `LIVE_DAILY_BUY_LIMIT`(기본 500만 원), 1억 원 이상 주문은 보내지 않음
  - 주문 POST 는 HTTP 계층에서 재시도하지 않습니다. 응답을 못 받으면 같은 `clientOrderId`(멱등키 10분)로만 다시 확인하고, 끝내 모르면 '접수 불명'으로 기록해 토스 앱 확인을 요청합니다.
  - 지정가는 KRX 호가단위에 맞춥니다(매수 내림, 매도 올림).
  - 계좌를 확인하지 못하면 기동 시 엔진을 일시정지합니다.
- 체결 반영: 토스 주문 조회는 주문 1건의 누적 체결(수량·평균가·수수료·세금)만 주므로, 1분마다 조회해 DB 에 기록된 체결과의 차이를 새 체결로 남깁니다.
- 모드 전환(모의 ↔ 실거래): 기록은 지우지 않고 계좌 기준 시각(`since`)만 새로 잡습니다. 에이전트 기억·매매 내역·주문/체결 목록·자산 곡선은 기준 시각 이후만 봅니다. 이전 모드의 미체결 주문 기록은 '모드 전환'으로 정리합니다(실제 토스 주문은 건드리지 않으므로 토스 앱 확인 안내).
- 검증 범위: 가짜 토스 서버(respx)로 요청 형식·상태 전이·체결 증분·거부·킬 스위치·모드 전환을 테스트했습니다. **실계좌로 실제 주문을 보내 본 적은 없습니다.** 처음 켤 때는 소액으로 확인하세요.

### D-35 트레이딩 룸 대화는 하루 단위로 이어짐, 매매 내역 도구
- 채팅 답변에 오늘(KST) 나눈 질문·답변·세션 요약을 넣습니다. DB 에서 읽으므로 재시작해도 이어집니다.
- 기동 안내는 하루 한 번만 채팅에 올리고, 같은 날 재시작은 감사 로그에만 남깁니다. 재시작 때문에 답을 못 받은 질문은 기동 후 이어서 답합니다.
- `get_trade_history` 도구와 채팅 문맥에 매매 원장(매도별 실현손익·사유·세션)을 넣었습니다. 실현손익 질문에 종목과 금액을 짚어 답합니다.
- 답변·세션 요약에서 "모의투자이며 투자 권유가 아닙니다" 같은 면책 문장을 빼도록 프롬프트를 바꾸고 필터를 더했습니다. 화면 하단 고지는 유지합니다.


### D-36 트레이딩 룸 활동 표시와 상태 복원 (서버가 기준)
- 도구 호출 메시지에 데이터 출처·소요 시간·단계·성공 여부·결과 한 줄 요약(`line`)을 함께 저장합니다(`app/agent/activity.py`). 요약은 도구가 돌려준 값만 씁니다.
- 판단 세션 진행 상황(단계·경과·도구 사용 수·출처별 횟수·토큰)과 '생각 중' 표시는 서버(`AgentRunner.progress`)가 들고 있고, WebSocket `progress` 채널과 `GET /api/agent/progress` 로 보냅니다. 화면은 처음 열 때와 재접속할 때마다 채팅·진행 상황을 서버에서 다시 받아, 어느 기기에서 열어도 같은 상태를 봅니다.
- 세션 표시와 답장 표시를 따로 관리해, 세션 중에 답장이 끝나도 세션의 '생각 중' 표시가 지워지지 않습니다.
- 채팅 답장은 한 번에 하나만 씁니다. 답하는 동안 들어온 질문(새로고침 후 다시 보낸 질문 포함)은 끝난 뒤 한 번에 묶어 답합니다. 답장마다 어느 질문까지 보고 답했는지(`question_id`)를 남겨 같은 질문에 두 번 답하지 않고, 실패해도 무한 재시도하지 않습니다.
- 다른 곳에서 접속할 때는 Tailscale `serve`(내 tailnet 전용, 인터넷 공개 아님)를 씁니다. README 2-4 참고.

### D-37 모바일 화면 (760px 이하)
- 휴대폰에서 Tailscale 로 접속해 에이전트를 지켜보는 용도를 우선합니다. 데스크톱 화면은 바꾸지 않습니다.
- 사이드바 메뉴는 하단 탭바(짧은 이름: 홈·채팅·구조·자산·백테스트·설정·로그)로 바뀌고, 상단 바는 로고·모드 배지·연결 점·킬 스위치 한 줄 + 상태 칩 한 줄(가로 스크롤)로 줄입니다. 킬 스위치는 항상 첫 화면에 보입니다.
- 대시보드는 지표 다음에 트레이딩 룸을 먼저 보여 줍니다. 표는 카드 안에서 가로로 스크롤하고, 한 열 레이아웃은 `minmax(0, 1fr)` 로 넓은 표가 화면을 밀어내지 않게 합니다.
- iOS 확대 방지를 위해 채팅 입력창 글자는 16px, 아이폰 하단 홈 막대 영역(safe-area)을 비웁니다. '홈 화면에 추가' 시 앱처럼 열리도록 메타 태그를 넣었습니다.

### D-38 휴대폰 화면을 앱처럼 (스크롤·화면 전환)
- 데스크톱(761px 이상)은 바꾸지 않습니다. 새 감싸개(`.page-scroll`, `.page`)는 넓은 화면에서 `display: contents` 로 상자 없이 지나가고, 지금처럼 `.content` 가 스크롤합니다. 아래 동작은 모두 휴대폰 폭에서만 켜집니다(`src/mobile.ts`).
- 앱 틀: 상단 바 · 본문 · 하단 탭바를 세로 flex 로 쌓고 본문(`.page-scroll`) 하나만 스크롤합니다. body 는 스크롤하지 않고(`overflow: hidden`, `overscroll-behavior: none`) 본문은 `overscroll-behavior: contain` 이라 고정 바 뒤에서 화면이 출렁이지 않습니다. 탭바는 `position: fixed` 대신 마지막 줄이라 본문을 가리지 않습니다.
- 탭별 스크롤 위치를 기억해 돌아오면 복원하고(내용이 늦게 차면 몇 프레임 더 시도, 손가락이 닿으면 중단), 보고 있는 탭을 다시 누르면 맨 위로 올립니다. 본문을 내리면 상단 바에 그림자가 생깁니다(높이는 그대로 — 높이를 줄이면 스크롤이 튐).
- 탭 전환은 View Transitions API 로 본문만 진행 방향으로 16px 밀며 바꾸고(0.26초), 탭 선택 표시는 새 위치로 미끄러집니다. `BrowserRouter` 는 이동을 `startTransition` 으로 감싸 react-router 의 `viewTransition` 을 쓸 수 없어, 새 화면이 그려진 뒤 끝나는 Promise 로 직접 감쌉니다. 지원하지 않는 브라우저와 탭이 아닌 이동(종목 상세·뒤로 가기)은 본문이 살짝 떠오르는 CSS 효과만, `prefers-reduced-motion` 이면 효과 없이 바로 바뀝니다. 새 의존성은 없습니다.
- 터치: 회색 탭 하이라이트 제거, 버튼·탭 눌림(축소) 표시, 버튼·입력창 44px(킬 스위치는 보이는 크기는 그대로 두고 누름 영역만 넓힘), 컨트롤 글자 선택 방지, 모든 입력창 16px(iOS 확대 방지).
- 키보드: 보이는 높이(`visualViewport`)를 `--vvh` 로 앱 높이에 쓰고, 안드로이드 크롬은 `interactive-widget=resizes-content` 로 화면을 줄입니다. 글자를 입력하는 동안에는 탭바를 숨겨(`kb-open`) 트레이딩 룸 입력창이 키보드 바로 위에 옵니다. 트레이딩 룸 채팅 카드는 본문 높이(`--scroll-h`)를 꽉 채웁니다. 채팅은 맨 아래에 붙어 있을 때 메시지 내용이 바뀌거나 창 크기가 바뀌어도(키보드·진행 표시) 아래를 유지합니다 — 이 부분은 넓은 화면에도 적용되며, 맨 아래에 있지 않을 때는 지금처럼 움직이지 않습니다.
- '홈 화면에 추가': 최소 웹 앱 매니페스트(`public/manifest.webmanifest`, standalone)와 아이콘(SVG + PNG 192/512/180), 휴대폰 폭 전용 상태 표시줄 색(상단 바와 같은 흰색/어두운 패널)을 넣었습니다.
- 에이전트 구조 화면은 데이터를 받는 동안 휴대폰에서 카드 모양 자리 표시를 보여 줍니다(넓은 화면은 '불러오는 중…' 글자 그대로).
- 검증: Chromium(Playwright, 390×844) 기준입니다. iOS Safari 의 키보드 동작(`visualViewport`)은 실기기에서 확인하지 않았습니다.

### D-39 휴대폰 알림 (Web Push)
- 네이티브 앱(Capacitor) 대신 지금 웹앱에 Web Push 를 붙였습니다. 아이폰은 iOS 16.4 부터 '홈 화면에 추가'한 웹앱이 푸시를 받을 수 있어 앱스토어·Xcode 없이 알림을 받습니다. 서버는 계속 이 컴퓨터에서 돌고, 앱은 Tailscale HTTPS 주소로 엽니다.
- 감사 로그가 남을 때 `EventHub.listeners` 로 `PushNotifier.on_audit` 이 불려, 알릴 이벤트만 알림으로 바꿉니다: 체결(FILL) · 리스크 차단(RISK_BLOCK) · 킬 스위치/오류(KILL_SWITCH·ERROR) · 판단 세션 끝/일일 리포트(AGENT_RUN·REPORT, 기본 꺼짐). 실거래 모드면 제목 앞에 `[실거래]` 를 붙입니다. 알림 내용은 감사 로그에 있는 값만 씁니다.
- 발송은 `pywebpush==2.5.0`(VAPID 서명 + aes128gcm 암호화)을 스레드에서 돌리고, 기기별로 따로 보내 한 기기 실패가 다른 기기를 막지 않습니다. 푸시 서비스가 404/410 을 주면 해지된 기기로 보고 목록에서 지웁니다. 알림은 6시간 동안 보관(TTL)되어 휴대폰이 잠시 꺼져 있어도 받습니다.
- VAPID 개인키는 `.env`(`VAPID_PRIVATE_KEY`)로만 받습니다. 비어 있으면 `./run.sh` 가 표준 라이브러리로 P-256 키를 만들어 `.env` 에 넣고 값은 출력하지 않습니다. 로그 마스킹 대상에 포함했습니다. 키가 없거나 잘못되면 알림만 꺼지고 앱은 그대로 돕니다.
- 구독 주소(endpoint)는 기기별 비밀 주소라 API 응답·로그에 내보내지 않고, 기기는 주소의 해시(`id`)로만 보여 줍니다. 서버가 임의 주소로 요청을 보내지 않도록 애플·구글·모질라·MS 푸시 서비스 주소만 구독으로 받습니다. 구독과 알림 종류 설정은 `app_settings` 의 `push` 키에 둡니다(마이그레이션 없음, 기기 최대 20대).
- 화면: 설정 → 휴대폰 알림 카드에서 켜기·테스트·끄기·종류 선택·기기 목록. 서비스 워커(`public/sw.js`)는 알림 표시와 누르면 해당 화면 열기만 하고 캐시는 하지 않습니다(항상 최신 화면).
- 검증: 발송은 요청을 가로채 서명·암호화 헤더까지 확인하는 테스트로 봤고(외부 호출 없음), 실제 아이폰 수신은 사용자가 확인합니다.

### D-41 LLM 비용 예상 (월별 토큰 사용량 → 상용 모델 요금 환산)
- 지금 모델(자체 서버)은 API 요금이 없지만, 같은 사용량을 OpenAI·Google·Anthropic 모델로 돌렸을 때의 요금을 미리 봅니다. 'LLM 비용' 화면과 `GET /api/llm/costs`.
- LLM 호출마다 입력·출력 토큰을 `llm_usage` 테이블에 남깁니다(판단 세션 = `session`, 채팅 답장 = `chat`). 예전 판단 세션은 세션 합계만 있어서 마이그레이션 0002 가 세션당 한 줄로 가져옵니다(`source=backfill`, 호출별 내역·캐시 추정 없음, 규칙 세션 제외).
- 요금표는 `app/agent/costs.py` 의 `MODELS` 에 있고, 2026-11-04 에 각 회사 공식 가격표(Anthropic `platform.claude.com/docs/en/about-claude/pricing`, OpenAI `developers.openai.com/api/docs/pricing`, Google `aistudio.google.com/docs/pricing`)에서 확인한 값입니다. 회사마다 최상위·주력·중간·경량 4개씩 12개 모델입니다. 호출 1회 입력이 기준을 넘으면 장문 요금(Haiku 5.5 10만, GPT-6 Astra 27.2만, Gemini 3.1 Pro 20만), 예정된 인상(Gemini 4 Argon 2026-12-01, Gemini 3.8 Flash 2027-01-01)은 그 날짜부터 반영합니다.
- '캐시 적용' 시나리오: 판단 세션은 매 호출마다 지금까지의 대화를 다시 보내므로, 바로 전 호출의 입력 토큰만큼을 다음 호출의 캐시 적중으로 추정합니다. OpenAI·Google 은 자동 캐시라 적중분만 할인, Anthropic 은 `cache_control` 이 필요하고 새로 쓰는 부분에 5분 캐시 쓰기 요금(입력의 1.25배)을 붙입니다. 단발 답장과 예전 합계는 캐시 없이 계산합니다. '캐시 없음' 시나리오도 함께 보여 줍니다.
- 이번 달 예상 = 이번 달 지금까지 + (최근 30일 중 사용한 날의 하루 평균 × 남은 거래일). 원화는 토스 원/달러 환율로 바꿉니다.
- 한계: 토큰 수는 지금 모델의 토크나이저 기준이라, 같은 글도 다른 회사 모델에서는 토큰 수가 달라 실제 청구액과 차이가 납니다. 추론(thinking) 토큰은 지금 모델이 출력에 포함해 보고한 만큼만 셉니다. Gemini 명시적 캐시 보관료·배치 할인·지역 처리 할증은 넣지 않았습니다.

### D-42 OpenAI Responses API, 모델별 매개변수 맞추기, 테스트용 LLM 엔드포인트 분리
- OpenAI 추론형 모델(gpt-6.1-sol 등)은 Chat Completions 에서 추론과 도구 호출을 함께 쓸 수 없다고 응답합니다("use /v1/responses"). `LLM_API=auto` 이면 `api.openai.com` 은 Responses API(`POST /responses`), 그 밖(vLLM·Gemini 호환 등)은 지금처럼 Chat Completions 를 씁니다. `chat`/`responses` 로 직접 고를 수도 있습니다.
- Responses 경로는 공식 문서(function calling·reasoning 가이드) 형식을 따릅니다: 평평한 도구 정의, `tool_choice: {type:"function", name}`, `function_call_output` 으로 도구 결과, `max_output_tokens`(추론 토큰 포함), `reasoning.effort`(`LLM_REASONING_EFFORT`, 비우면 모델 기본). 도구 호출이 이어질 때 응답의 추론·도구 호출 항목을 그대로 다음 요청에 되돌려 보냅니다(공식 권장). `store: false` 로 포트폴리오·매매 내역을 OpenAI 대화 저장소에 남기지 않습니다(추론 항목은 암호화돼 돌아옴).
- 사용량은 `input_tokens`·`output_tokens` 를 기존 이름(prompt/completion)으로 바꾸고, 실제 캐시 적중(`cached_tokens`)·추론 토큰(`reasoning_tokens`)도 함께 남깁니다.
- 모델마다 받는 매개변수가 달라(`max_tokens` → `max_completion_tokens`, `temperature` 거절), 서버가 `unsupported_parameter/value` 로 거절하면 그 매개변수만 바꾸거나 빼고 다시 보내며 기억합니다. 다른 400 오류는 다시 보내지 않습니다.
- 테스트용 엔드포인트(`LLM_TEST_*`)를 실서비스(`LLM_*`)와 분리했습니다. 앱(판단·답장)은 실서비스만 쓰고, 코드를 고친 뒤 실제 호출 확인은 `./run.sh llm-check`(짧은 요청 4개: 일반 답·도구 호출·강제 호출·도구 결과 되돌려 받기)로 테스트용에만 보냅니다. 테스트용이 비어 있으면 실서비스로 넘어가지 않고 멈추며, 실서비스로 점검하려면 `--live` 를 직접 붙여야 합니다.

### D-43 LLM 무료/유료 전환 (설정 화면)
- `.env` 의 두 묶음을 화면에서 골라 씁니다: **무료 = `LLM_TEST_*`**(테스트용·무료 엔드포인트, 예: 자체 서버), **유료 = `LLM_*`**(실서비스·과금). 설정 → 'LLM 모델' 카드, 상단 바에 `무료 · 모델` / `유료 · 모델` 로 표시합니다.
- 고른 값은 `app_settings` 의 `llm_profile` 에 남아 재시작해도 유지됩니다. 저장값이 없거나 그 묶음이 비어 있으면 유료(설정돼 있으면) → 무료 순으로 고릅니다.
- 판단 세션이나 답장이 진행 중이면 바꾸지 않습니다(409) — 한 세션 안에서 모델이 섞이지 않게. 비어 있는 묶음은 고를 수 없습니다(400). 바꾸면 감사 로그(CONFIG)와 트레이딩 룸 안내를 남기고 다음 판단·답장부터 적용합니다. 유료로 바꿀 때는 화면에서 과금 확인을 한 번 더 받습니다.
- 화면 API(`/api/system`, `/api/llm/profile`)에는 모델 이름과 호출 방식만 내보내고, LLM 서버 주소(내부 IP 일 수 있음)와 키는 내보내지 않습니다. 이전에 내보내던 `llm.host` 는 뺐습니다.
- `./run.sh llm-check` 는 그대로 무료(테스트용) 묶음으로 점검하고, `--live` 는 유료 묶음입니다.

### D-44 네이버 뉴스: NAVER API HUB 지원, 키 인증 실패 표시, 점검 명령
- 2026-11-04 판단 세션에서 뉴스 검색이 모두 실패했고, 매니저는 "뉴스 검색이 막혔네요"라고만 남겼습니다. 실제 호출로 확인하니 개발자센터 주소(`openapi.naver.com`)가 `HTTP 401`, `errorCode 024`("Authentication failed")로 키를 거절했습니다. 키는 네이버 클라우드 **NAVER API HUB** 에서 받은 것이었고, API HUB 는 주소·헤더가 다릅니다.
- `NAVER_API` 로 키를 받은 곳을 고릅니다(기본 `hub`). 둘 다 공식 문서 형식을 따르고, 요청 파라미터(`query`·`display`·`start`·`sort`)와 응답(`items[]`)은 같습니다.
  - `hub`: `GET https://naverapihub.apigw.ntruss.com/search/v1/news?format=json`, 헤더 `X-NCP-APIGW-API-KEY-ID`·`X-NCP-APIGW-API-KEY` (api.ncloud-docs.com `naver-api-hub-search-news`, `naver-api-hub-overview`). 종량제지만 공식 문서상 현재 한시 무료이며, 검색 API 하루 한도는 25,000회입니다.
  - `developers`: `GET https://openapi.naver.com/v1/search/news.json`, 헤더 `X-Naver-Client-Id`·`X-Naver-Client-Secret`.
  - 한쪽이 실패했을 때 다른 쪽으로 몰래 넘어가지 않습니다(키 두 벌을 섞지 않도록 설정으로만 고름).
- 401 을 받으면 이유와 고칠 곳(어느 화면의 어떤 값을 `.env` 어디에 넣는지, 재시작)을 오류 메시지로 돌려줘 매니저가 정확히 전합니다. 같은 키로는 결과가 바뀌지 않으므로 재시작 전까지 네이버를 다시 부르지 않습니다. 429(하루 한도 초과)·400 등은 그대로 다음 검색을 시도합니다. 오류 본문은 검색 API 형식(`errorCode`)과 API 게이트웨이 형식(`error.errorCode`)을 모두 읽습니다.
- 에이전트 화면의 데이터 출처 칩에 `○ NAVER · 키 인증 실패`, `search_news` 도구에 '연결 안 됨'을 표시합니다. 키 값은 어디에도 나오지 않습니다.
- `./run.sh news-check [검색어]`: 실제 검색 1회(3건)로 키를 점검합니다.

### D-45 유료 LLM 모델 고르기 (제공사 자동 판별 + 설정 화면 드롭다운)
- `.env` 의 `LLM_*` 로 제공사를 알아냅니다. `LLM_BASE_URL` 주소(`api.openai.com` → OpenAI, `generativelanguage.googleapis.com` → Google, `api.anthropic.com` → Anthropic)가 우선이고, 주소가 비어 있으면 키 모양(`sk-ant-` → Anthropic, `sk-` → OpenAI, `AIza`·`AQ.` → Google)으로 판단해 공식 주소를 씁니다. 그 밖의 주소(자체 서버·게이트웨이)는 제공사를 모르는 것으로 보고 `LLM_MODEL` 만 씁니다.
- 설정 → 'LLM 모델' 카드의 유료 쪽에 드롭다운을 둡니다. 모델 목록은 비용 화면과 같은 표(`app/agent/costs.py` 의 `MODELS`, 2026-11-04 공식 가격표 기준 12개)이고, 오늘 기준 입력·출력 단가를 같이 보여 줍니다. 판별된 제공사의 모델만 고를 수 있고, 다른 회사 모델은 "키가 .env 에 없어요"로 막습니다. `LLM_MODEL` 이 표에 없으면 '(.env)' 항목으로 맨 앞에 둡니다.
- 고른 모델은 `app_settings` 의 `llm_paid_model` 에 남아 재시작해도 유지됩니다. `.env` 를 다른 회사 키로 바꿔 저장값을 쓸 수 없게 되면 `LLM_MODEL` 로 돌아갑니다. 판단 세션·답장이 진행 중이면 바꾸지 않고(409), 바꾸면 감사 로그(CONFIG)와 트레이딩 룸 안내를 남깁니다. 무료를 쓰는 중에 바꾸면 저장만 하고 유료로 돌아갈 때 그 모델을 씁니다. 화면에서는 과금 확인을 한 번 더 받습니다.
- 호출 방식(`LLM_API`)과 추론 강도(`LLM_REASONING_EFFORT`)는 모델과 관계없이 그대로 적용됩니다. 고른 모델이 그 추론 강도를 받지 않으면 OpenAI 가 400 으로 거절하니, 그때는 `.env` 의 값을 비우거나 맞춥니다.
- **Anthropic 은 목록에만 있고 고를 수 없습니다.** Anthropic 공식 가이드는 OpenAI 호환 방식이 아니라 전용 Messages API 를 쓰라고 하고, Claude Opus 5.5·Sonnet 5.5 는 이 앱이 세션 마지막에 쓰는 도구 강제 호출(`tool_choice` 로 특정 도구 지정)을 400 으로 거절합니다. Anthropic 전용 연결(Messages API, 강제 호출 대신 `auto` + 지시문)을 만든 뒤에 엽니다.

### D-46 테스트용(무료) LLM 을 설정 화면에서 지정 (+ Responses API 거절 형식 보정)
- 설정 → 'LLM 모델' 카드에서 테스트용 LLM 의 주소·모델·호출 방식·추론 강도를 바꿉니다. 값은 `app_settings` 의 `llm_test_override` 에 남아 재시작해도 유지되고, 비운 항목은 `.env` 의 `LLM_TEST_*` 를 씁니다. '.env 값으로 되돌리기'로 지웁니다.
- `.env` 파일 자체는 고치지 않습니다. 컨테이너는 `.env` 를 시작할 때 환경변수로만 읽고(파일을 붙이지 않음), 앱이 `.env` 를 쓰려면 비밀키가 든 파일을 컨테이너에 쓰기 가능하게 열어야 해서입니다. **키는 화면에서 받지 않고** `.env` 의 `LLM_TEST_API_KEY` 만 씁니다. 키를 받지 않는 자체 서버면 키 없이도 쓸 수 있습니다(Authorization 헤더를 보내지 않음).
- '모델 목록 불러오기'는 그 서버의 OpenAI 호환 `GET {주소}/models` 를, '연결 확인'은 `./run.sh llm-check` 와 같은 짧은 요청 4개를 **테스트용 엔드포인트에만** 보냅니다(유료로는 보내지 않음).
- 같이 고친 것: OpenAI Responses API 는 지원하지 않는 매개변수를 `code: null` 과 메시지("Unsupported parameter: 'temperature' …")로만 거절합니다. D-42 의 자동 맞춤이 `code` 만 보고 있어 2026-11-04 세션 #72 가 실패했습니다. 이제 메시지 형식도 알아보고, 고른 모델이 추론 강도(`reasoning.effort`)를 거절하면 그 값을 빼고 모델 기본값으로 보냅니다. 실제 응답 형식으로 테스트를 추가했습니다.

### D-50 OpenRouter 를 유료 제공사로 추가
- `LLM_BASE_URL=https://openrouter.ai/api/v1`(또는 주소를 비우고 `sk-or-` 로 시작하는 키)이면 제공사를 OpenRouter 로 봅니다. 키 판별은 `sk-ant-` → `sk-or-` → `sk-` 순서입니다. 호출은 Chat Completions(`POST /chat/completions`, 도구 호출 지원)입니다. 출처: openrouter.ai/docs/quickstart, API reference(chat·models).
- 모델 목록은 고정 표가 아니라 OpenRouter 의 `GET /api/v1/models` 에서 받습니다. 판단 세션은 도구 호출과 도구 지정(`tool_choice`)이 필요하므로 `supported_parameters` 에 `tools`·`tool_choice` 가 모두 있는 모델만 보여 줍니다. 단가(토큰당 USD 문자열)는 100만 토큰당으로 바꿔 표시합니다. 목록은 6시간 메모리 캐시이고, 화면이 비었거나 오래됐을 때 `POST /api/llm/openrouter/models/refresh` 로 다시 받습니다. 실패하면 이전 목록을 유지하고 이유를 보여 줍니다.
- OpenRouter 키로는 OpenAI·Google·Anthropic 직접 연결 모델(비용 표 12개)을 보여 주지 않습니다(그 키로 부를 수 없음). 같은 회사 모델은 OpenRouter 목록 안에서 회사별로 묶여 나옵니다.
- 선택 헤더(`HTTP-Referer`·`X-OpenRouter-Title`)는 공개 순위 표시용이라 보내지 않습니다.
- 비용 예상 화면(D-41)은 아직 OpenRouter 모델 단가를 쓰지 않습니다(후속 과제: 캐시된 목록 단가로 환산).

### D-48 미장(미국 주식) 모의투자 — 같은 프로세스의 두 번째 시장
- ~~항상 모의투자~~ → D-55 에서 바뀜: 미장 거래 모드는 `US_TRADING_MODE` 로 국장과 따로 정합니다(기본 모의). `paper_only` 는 이제 "지금 이 시장이 모의계좌인지"입니다.
- 구조: 국장 시스템은 그대로 두고, 같은 서버 안에 미장 전용 묶음(엔진·모의계좌·스케줄러·매니저·이벤트)을 하나 더 만듭니다. DB 도 따로 씁니다(`US_DATABASE_URL`, 기본 `sqlite:///{DATA_DIR}/us_market.db`, 같은 마이그레이션 적용). 토스 클라이언트는 **하나를 같이 씁니다** — 토스는 클라이언트당 유효 토큰이 1개라 따로 발급하면 서로의 토큰을 끊습니다. 로그인·휴대폰 알림·네이버 뉴스·LLM 설정도 공유합니다.
- 시장 정보는 `app/core/market.py` 의 `MarketSpec`(통화·시간대·종목 시장·랭킹 국가·수수료·초기 자금·국장 전용 도구 여부)에 모았습니다. 국장 값은 기존 동작과 같습니다.
- 거래일은 **뉴욕 날짜**입니다. 미장 정규장은 한국 시각으로 자정을 넘기므로(지금은 23:30~06:00, 서머타임에는 22:30~05:00), 엔진·모의계좌·리포트·'오늘' 대화·당일 손익의 날짜 계산을 시장 시간대 기준(`cal.local_date()`)으로 바꿨습니다. 국장은 한국 날짜라 결과가 같습니다. 서머타임은 zoneinfo 로 처리합니다.
- 장 캘린더: NYSE 2026~2027 휴장일과 13:00 조기 폐장(nyse.com/markets/hours-calendars, 2026-11-04 확인) + 토스 `GET /api/v1/market-calendar/US` 의 전일·당일·익일 값이 우선합니다.
- 주문: 개장 30분 전(시가 체결)부터 마감 10분 전까지(현재가 체결) 받습니다. 가격은 $1 이상 0.01, 미만 0.0001 단위, 정수 주식만, 수수료 0.1%(`PAPER_US_COMMISSION_RATE`, 토스 명세 예시값), 거래세 없음, SEC·FINRA 수수료는 넣지 않았습니다. 초기 자금 $10,000(`PAPER_US_INITIAL_CASH`), 1회 주문 한도 기본 $1,500.
- 종목: 토스 `stocks/all` 의 NASDAQ·NYSE·AMEX 에서 보통주·ETF, 순위는 `rankings?marketCountry=US`. 관심종목이 비어 있으면 AAPL·MSFT·NVDA·AMZN·GOOGL·META·TSLA·QQQ·SPY 로 시작합니다.
- 매니저: 국장 전용 도구(수급·DART 재무·공시)는 빼고, 시장 개요는 QQQ·SPY·DIA·미국 섹터·상승/하락 상위·원/달러로 만듭니다. 뉴스는 네이버(한글 검색어), 구글 검색(D-49)은 키가 있으면 같이 씁니다.
- LLM: 미장 매니저의 무료/유료 선택은 국장과 따로입니다(`llm_profile_us`, **기본 무료**). 유료 모델·테스트용 LLM 설정을 바꾸면 그 선택을 쓰는 모든 시장에 적용됩니다.
- 일정(한국 시각, 매일 다시 계산): 개장 25분 전 장전 판단, `US_AGENT_INTERVAL_MINUTES` 간격 장중 판단, 마감 15분 뒤 리포트. 1분마다 도는 분배기가 (거래일, 작업)별로 한 번만 실행하고, 실행 기록을 남겨 재시작해도 다시 돌지 않습니다.
- API: `/api/us/...` 는 `/api/...` 와 같은 엔드포인트를 미장 묶음으로 처리합니다(로그인·알림·LLM 설정 등 공용 항목 제외). `/api/markets`(시장별 상태), `/api/overview`(두 시장 요약 + 토스 환율로 환산한 원화 합계), `/ws/events?market=US`.
- 확인 못 한 것: 토스의 미국 ETF·ADR `securityType` 값(ETF 를 `ETF` 로 가정), 미국 일봉 시각(뉴욕 자정 가정), DIA 시세 제공 여부, 조기 폐장이 토스 캘린더에 `regularMarket.endTime` 으로만 반영되는지. 비용 화면(D-41)은 아직 국장 DB 의 사용량만 셉니다.

### D-49 구글 검색 도구 (Gemini 'Google 검색 그라운딩', 유료)
- 구글 일반 웹 검색 API(Custom Search JSON API)는 신규 가입이 막혔고 2027-01-01 종료 예정입니다(developers.google.com/custom-search/v1/overview). 그래서 공식적으로 남은 방법인 Gemini API 의 Google 검색 도구를 씁니다(`app/research/google.py`). 구글 뉴스 RSS 는 공식 문서가 없고 약관상 자동 수집 제한이 있어 쓰지 않습니다.
- `.env`: `GEMINI_API_KEY`(비우면 꺼짐, 로그 마스킹), `GOOGLE_SEARCH_MODEL`(기본 gemini-3.5-flash-lite), `GOOGLE_SEARCH_MAX_PER_SESSION`(기본 3).
- 요금(2026-11-04, aistudio.google.com/docs/pricing): **유료 등급에서만** 됩니다. 검색은 월 5,000회 무료, 그 뒤 1,000회당 $14, 토큰 요금은 별도. 무료 등급에는 검색 그라운딩이 없습니다.
- 도구 `search_web {query, days 1~7, limit}` 를 국장·미장 모두에 둡니다. 기간은 `googleSearch.timeRangeFilter`(startTime 포함·endTime 미포함)로 최근 N일로 제한합니다. 키가 없으면 매니저 도구 목록에서 빠지고 에이전트 구조 화면에 "GEMINI_API_KEY 없음 (유료)"로 보입니다.
- 세션당 한도는 세션 번호로 셉니다(LLM 이 준 값은 무시). 국장·미장 세션 번호가 겹치므로 시장마다 따로 셉니다.
- 매니저에게는 요약 답·출처(제목·주소)·남은 횟수를 주고, 화면 칩은 검색어와 "결과 N건"만 보여 줍니다. 결과를 화면에 그대로 보여 주려면 Search Suggestions 를 함께 표시해야 한다는 약관 때문입니다.
- 검증은 가짜 응답(respx)으로만 했습니다. 실제 Gemini 호출·결제는 확인하지 않았습니다(유료).

### D-51 판단 일정: 시작·끝·주기 (자정 기준 딱 떨어지는 시각)
- 설정 → 판단 주기(국장 `/api/schedule`, 미장 `/api/us/schedule`)에서 정합니다. 시장마다 따로 저장됩니다(kv `schedule`).
- 판단 시각 = [시작, 끝](양 끝 포함) 안에서 **자정부터 센 분이 주기로 나누어떨어지는 시각**입니다. 예: 08:00~17:00·1시간 → 08:00, 09:00, …, 17:00 / 15분 → 08:00, 08:15, … . 15:33 에 바꿔도 15:33 에 돌지 않고 다음 슬롯부터 돕니다.
- 시각은 시장 현지 시각입니다(미장은 뉴욕 시각이라 서머타임이 날짜마다 반영되고, 화면에 한국 시각을 같이 보여 줌). 시작·끝은 5분 단위, 주기는 5·10·15·20·30·60·120·180·240분, 하루 최대 96회. 0회이거나 끝 ≤ 시작이면 거절합니다.
- 거래일에만 돕니다. 장 시작 전 슬롯은 장전 판단, 그 뒤는 정시 판단입니다. **장 시간 밖 슬롯(장전 접수 30분 전보다 이르거나 주문 마감 시각부터)** 도 판단은 하지만 주문은 기존 접수 규칙대로 받지 않습니다. 화면에 따로 표시합니다. 리포트는 마감 15분 뒤입니다.
- 저장하지 않으면(또는 '기본값으로') `.env` 일정 그대로입니다: 국장 08:35 + `AGENT_INTERVAL_MINUTES` 장중 + 15:45 리포트, 미장 개장 25분 전 + 장중 + 마감 15분 뒤.
- 국장도 미장과 같은 1분 분배기로 바꿨습니다. 설정을 매 분 다시 읽어 재시작 없이 적용되고, 저장 시각까지의 슬롯은 실행 기록에 넣어 늦게 돌지 않습니다. 재시작 후 10분 안에 놓친 슬롯은 실행하고, 리포트는 진행 중인 판단이 끝나길 기다렸다 만듭니다. 토스 장 운영 캘린더는 현지 날짜마다 한 번 반영합니다.
- 바꾸면 감사 로그와 트레이딩 룸에 한 줄("⏰ 판단 일정을 바꿨어요: …")을 남깁니다. 에이전트 구조 화면·`/system`·비용 예상(하루 세션 수)이 같은 일정을 씁니다.

### D-52 메모 카드 (사용자가 관리하는 매니저의 기억)
- '최근 사용자 메시지 5개 자동 주입'(D-47) 때문에 며칠 전 언급이 계속 판단에 끼어들었습니다. 이제 사용자가 카드로 직접 관리합니다: **관심 종목·주목할 종목·피할 종목·운용 지시**. 종목은 코드나 이름으로 검색해 추가하고, 켜기/끄기·만료일·메모를 정합니다(`memory_cards` 테이블, 마이그레이션 0003, 시장마다 따로).
- 켜져 있고 만료되지 않은 카드만 판단·답장 프롬프트에 들어갑니다(최근 판단 기록보다 앞). 만료일은 그 시장 현지 날짜이고 그날까지 유효합니다.
- 피할 종목은 프롬프트로 막습니다(매수 금지, 보유 중이면 유지·매도만). 최종 방어선은 리스크 엔진이고, 리스크 규칙은 바꾸지 않았습니다. 규칙 기반 모드(LLM 없음)는 카드를 쓰지 않습니다.

- 관심 종목 카드는 관심종목 목록(시세 갱신)에도 넣습니다. 카드를 지워도 관심종목 목록에서는 빼지 않습니다(따로 관리하는 목록).

### D-55 미장 실거래 (사용자가 켜는 것, 국장과 따로)
- 처음(D-48)에는 미장을 코드로 항상 모의투자로 막았습니다. 하지만 실거래 여부는 사용자가 정하는 것이고, 토스 Open API 는 미국 주식 주문을 지원합니다(openapi.json 1.2.28: 같은 `POST /api/v1/orders`, `symbol` = 영문 티커, `price` = 달러 소수, 금액 주문 `orderAmount` 은 US 시장가 전용, 소수점 수량은 US 시장가 매도만). 그래서 국장과 같은 방식으로 **사용자가 `.env` 에서 켜게** 바꿨습니다.
- 켜는 법: `US_TRADING_MODE=live` + `US_LIVE_TRADING_CONFIRM=I_UNDERSTAND_REAL_MONEY`. 국장 확인 문구로는 켜지지 않습니다. `US_MARKET_ENABLED=false` 면 무시합니다. 기본은 모의입니다.
- 브로커: 국장 실계좌 브로커(`TossLiveBroker`)에 시장 정보(`MarketSpec`)를 넘겨 같이 씁니다.
  - 잔고: `marketCountry=US` 만 씁니다. 소수점 보유분은 정수 부분만 봅니다.
  - 주문가능금액: `buying-power?currency=USD`. 날짜는 뉴욕 날짜입니다.
  - 지정가: `$1 이상 0.01·미만 0.0001` 로 맞춥니다(매수 내림·매도 올림, 토스 절삭에 맡기지 않음).
  - 주문: 정수 수량만, `timeInForce=DAY` 입니다.
- 안전장치
  - 하루 매수 총액 상한 `US_LIVE_DAILY_BUY_LIMIT`(달러, 기본 3,000)을 둡니다.
  - 토스가 1억 원 이상 주문에 확인을 요구하므로 원화 환산 1억 원 이상은 보내지 않습니다. 환율은 토스 `/exchange-rate` 이고, 실패하면 2,000원/달러로 보수적으로 잡습니다.
  - 주문 POST 는 재시도하지 않습니다(국장과 같음).
- 장 시작 전 주문 없음: 토스 미장은 데이·프리마켓이 따로 있습니다. 그래서 장전에 낸 `DAY` 주문이 어느 세션에서 체결되는지 명세만으로 알 수 없습니다. 실거래면 장전 접수 구간을 없애고(`UsMarketCalendar(pre_open=False)`), 기본 일정의 첫 판단을 장 시작 5분 뒤로 옮겼습니다. 장외 주문은 D-57 에서 사용자가 켠 세션에서만 받습니다.
- 국장도 실거래면 주문 클라이언트(`TossTradingClient`)를 같이 씁니다. 토스 주문 API 초당 한도는 계좌 하나에 걸리고, 토큰도 클라이언트 하나만 유효하기 때문입니다.
- 화면·API: `/api/us/system` 의 `trading_mode`·`paper_only`·면책 문구, 에이전트 구조(토스 실계좌·하루 한도), 기동 안내, 매니저 프롬프트(실계좌 설명)가 시장별 실제 모드를 따릅니다.
- 검증: 가짜 토스 서버(respx)로만 했습니다(`tests/test_us_live.py`). **실계좌로 미국 주식을 주문해 본 적은 없습니다.**
- 확인 못 한 것
  - 원화만 있을 때 자동 환전 주문이 되는지(달러 주문가능금액이 0이면 거부될 수 있음)
  - 미국 주문의 `commission`·`tax` 통화
  - 미국 주식에도 `opposite-pending-order-exists` 가 적용되는지

### D-57 장외 주문 켜기·끄기 (프리마켓·애프터마켓·미장 데이마켓)
- 설정 → 판단 일정·장외 주문에서 시장마다 켜고 끕니다(`GET/PUT /api/extended-hours`, `/api/us/extended-hours`, 시장 kv `extended_hours`). 기본은 모두 꺼져 있습니다(정규장만, 예전과 같음).
- 세션 시각은 토스 장 운영 캘린더(`/market-calendar/KR`·`/US`, 전일·당일·익일)가 날짜마다 준 값을 그대로 씁니다. 그래서 NXT 휴장·단축 운영과 미국 서머타임·휴장이 자동으로 반영됩니다.
  - 국장은 KRX+NXT 통합 기준입니다. 프리마켓은 `startTime ~ singlePriceAuctionStartTime`(접속매매, 시가단일가 전), 애프터마켓은 `singlePriceAuctionEndTime ~ endTime`(단일가 뒤 접속매매)입니다. 장전·장후 시간외종가는 토스 캘린더에 없어 다루지 않습니다.
  - 미장은 `dayMarket`(토스 데이마켓, 한국 낮)·`preMarket`·`afterMarket` 입니다.
  - 캘린더를 못 받은 날은 장외 세션이 없는 것으로 봅니다. 시각을 추측하지 않습니다.
- 접수 규칙(`fill_basis`)의 우선순위는 정규장(CLOSE) → 켠 장외 세션(EXT) → 장전 접수(OPEN) → 불가입니다. 국장은 프리마켓을 켜면 08:30~08:50 이 프리마켓 체결이 되고, 08:50~09:00 시가단일가는 예전처럼 시가 체결입니다.
- 모의 체결
  - 토스 `/prices` 의 `timestamp` 가 그 세션 시작 이후일 때만 현재가(±슬리피지)로 체결합니다. 장외 거래가 실제로 있을 때만 체결한다는 뜻입니다.
  - 시세가 장외 거래를 반영하는지는 명세에 없습니다. 그래서 반영하지 않으면 체결되지 않는 쪽으로 안전하게 둡니다.
  - 세션이 끝나면 미체결분을 `ext-session-expired` 로 취소합니다. 장외 주문의 거래일은 그 세션이 속한 토스 캘린더 날짜입니다.
- 실거래: 켠 세션에서 리스크 엔진이 주문을 받으면 토스로 바로 나갑니다(세션 지정 필드가 없어 접수 시각으로 결정됨). 손절·익절 감시와 1분 체결 동기화도 켠 장외 세션 동안(끝난 뒤 5분까지) 돕니다.
- 판단 일정 화면의 '장 시간 밖' 표시와 리스크 거부 사유, 주문 안내 문구가 같은 규칙을 씁니다.

  - **매니저·분석**: 매니저 · 백테스트 · 이벤트 로그

- 설정: 오른쪽 위 ⚙️ 버튼으로 옮겼습니다(휴대폰은 시장 전환 줄 오른쪽 끝). LLM 비용 화면은 설정에 속하는 화면으로 보고, 설정 목록의 '앱 공통' 안과 LLM 설정 링크로 들어갑니다. 그 화면에서는 ⚙️ 가 켜져 보입니다.
- 겹치던 길을 뺐습니다: 설정 화면의 '바로 가기'(뉴스 룸·LLM 비용·메모 카드) 묶음입니다. 메뉴에 있는 화면은 다시 두지 않습니다.
- 휴대폰 하단 탭은 7칸에서 5칸이 됐습니다: 홈 · 채팅 · 자산 · 뉴스 · **더보기**. 더보기는 아래 시트로 열리고 매니저 · 백테스트 · 이벤트 로그 · LLM 비용 · 설정(+ 로그아웃)을 담습니다. 탭바에 없는 화면에서는 '더보기' 칸이 켜져 보입니다. 넓은 화면 메뉴와 휴대폰 탭바는 한쪽만 그립니다(같은 링크가 두 번 읽히지 않게).
- 상단 바: 토스 시세 칩은 문제가 있을 때만 보입니다(정상이면 칩을 두지 않고, 문제가 있으면 경고 칩과 배너를 함께 띄움). PAPER/LIVE 배지·엔진 상태·킬 스위치는 안전에 관한 정보라 항상 보입니다.

### D-59 뉴스 룸 맨 위 '증시 영향 큰 뉴스' (섹션별 3줄)
- 뉴스 룸 맨 위(제목 카드 바로 아래)에 섹션마다 카드 하나: 그 섹션에서 주식시장(국내·미국 증시)에 영향이 가장 클 것 같은 이슈 3줄 + 줄마다 근거 기사 링크('기사 ›', 새 창). 넓은 화면은 격자, 휴대폰은 옆으로 넘기는 카드(scroll-snap)이고 이 상자의 가로 넘기기가 화면 넘기기(D-60)보다 먼저입니다(`data-no-swipe`). '접기/펼치기'는 이 기기에 기억합니다(localStorage `newsroom.impact.open`).
- 만드는 법: D-56 요약과 **같은 LLM 호출 하나**(지금 활성 LLM 프로필)에서 `impact {섹션: [{text, ref}]}` 도 받습니다. ref 는 그 섹션의 기사 번호이고 맞으면 그 기사 링크를 붙입니다(틀리면 링크 없음). 판을 만들 때 함께 DB(`news_editions.payload.sections[].impact`)에 저장하므로 화면을 열 때 LLM 을 부르지 않습니다. 줄당 90자, 3줄까지.
- LLM 이 없거나(미설정·요약 끔) 실패하거나 어떤 섹션을 빠뜨리면 그 섹션은 **규칙 기반**: 제목·요약문에 증시 관련 말(코스피·금리·환율·유가·관세·실적·반도체 등)이 많은 기사 → 많이 다뤄진 기사 → 원래 순서로 3개를 제목 그대로 씁니다. 화면에 'AI 요약 아님'으로 표시합니다(AI 로 만든 카드는 'AI'). D-59 전에 저장된 판은 읽을 때 규칙 기반으로 채웁니다(DB 는 그대로).
- 프롬프트는 오르내림을 단정하거나 매수·매도를 권하지 말라고 합니다. 새 `.env` 설정·마이그레이션은 없습니다.
- 검증은 가짜 응답(respx·vitest)과 로컬 가짜 서버 화면 확인으로만 했습니다. 실제 LLM(무료·유료)으로 3줄의 품질은 확인하지 않았습니다.

- (2026-11-05 수정) **요약은 섹션마다 따로** 묻고(동시에, 답이 잘리거나 JSON 이 아니면 한 번 더), 헤드라인은 받은 섹션 요약만 넣어 한 번 더 묻습니다.
  - 이유: 네 섹션을 한 번에 맡기면 무료 모델(추론형 Qwen)이 생각에 출력 한도를 거의 다 써서 답이 잘렸습니다. 실측으로 8,192 토큰 중 약 7,900 을 생각에 썼고, 답은 663자에서 끊겼습니다. `/no_think` 지시도 듣지 않았습니다. 섹션별로 묻자 섹션당 3~4.5천 토큰에서 끝났습니다.
  - 일부 섹션만 실패하면 그 섹션만 기사 목록과 규칙 기반 줄로 둡니다. 화면에는 "일부 섹션 요약 실패 (n/4)" 로 알립니다.
### D-60 휴대폰 제스처: 옆으로 넘기기 · 상단 바 접기 · 토스트 밀어 닫기
- **옆으로 넘기기**(`frontend/src/ui/swipe.ts`)
  - 하단 탭 화면(홈·채팅·자산·뉴스)에서는 옆 탭으로 넘어갑니다. 끝 탭에서는 멈추고, 넘겨서 더보기를 열지는 않습니다.
  - 그 밖의 화면(종목 상세·설정 주제·더보기 화면)에서는 오른쪽으로 넘기면 앱 안의 이전 화면으로 갑니다. 앱 안에 이전 화면이 없으면 그대로 둡니다.
  - 넘기는 동안 본문이 손가락을 조금 따라오고(최대 36px), 넘어갈 때 View Transition 으로 옆으로 밉니다. 안드로이드는 짧게 진동합니다.
  - 넘기지 않는 경우
    - 손가락 아래에 가로 스크롤 상자(지표 띠·표)·입력칸·차트·시트·`data-no-swipe` 가 있을 때 (그 상자의 가로 스크롤이 먼저)
    - 세로로 더 움직였을 때, 64px 미만일 때, 0.7초 넘게 끌었을 때
    - 키보드가 열려 있을 때
    - 홈 화면 앱이 아닐 때 화면 양 끝 20px 에서 시작한 경우 (브라우저의 가장자리 뒤로 가기에 양보)
- **상단 바 접기**: 내리면 상단 바의 둘째·셋째 줄(시장 전환·⚙️ 설정·상태 칩)을 접고, 조금이라도 올리면 다시 폅니다. 맨 위 56px 안에서는 항상 펴 둡니다. 첫 줄의 PAPER 배지·검색·킬 스위치는 늘 보입니다.
- **토스트**: 옆으로 56px 이상 밀면 닫힙니다.
- '동작 줄이기'를 켜면 따라오기·접기 애니메이션 없이 바로 바뀝니다. 넓은 화면은 바뀌지 않습니다.

### D-61 장외 세션 판단 · 알림 묶음 · 상단 바 고정 · 장 밖 실시간 갱신 · 포트폴리오 '전체' · 뉴스 5개 (2026-11-05)
- **장외 세션에서도 판단** (미장 데이·프리·애프터, 국장 NXT 프리·애프터)
  - 설정에서 켠 장외 세션 안에서도 판단 주기와 같은 '딱 떨어지는 시각'(시장 현지 시각, 자정 기준)에 판단합니다. 세션 끝 10분 전까지만 판단합니다.
  - 일정 범위(또는 기본 일정)와 겹치는 시각은 한 번만 돕니다.
  - 미장 데이마켓은 뉴욕 자정을 넘기므로(한국 낮), 그 거래일 일정에 붙여 계산합니다.
  - 세션 시각은 토스 장 운영 캘린더가 날마다 준 값(서머타임 반영)을 씁니다. 캘린더를 받지 못한 날은 장외 판단도 하지 않습니다.
  - D-57 이전에는 켠 세션에서 주문만 받았습니다. 판단 일정은 그대로라, 장외 시간에는 실제로 주문이 거의 나가지 않았습니다.
  - 설정 화면 이름은 '판단 일정·장외 거래', 카드 이름은 '🌙 장외 거래'로 바꿨습니다. 판단 미리 보기는 세션마다 판단 시각을 따로 보여 줍니다(`GET /api/schedule` 의 `extended`·`total`).
  - 미장 프롬프트의 "프리·애프터마켓 주문은 내지 않는다"는 켠 세션에 맞춘 안내로 바꿨습니다. 장외는 거래가 적어 가격이 튈 수 있으니 확신이 높을 때만, 작게 거래하라는 내용입니다.
- **알림 묶음**
  - 체결·리스크 차단은 한 건씩 보내지 않습니다. 판단 세션 중에 생긴 것은 세션이 끝날 때 알림 하나로 보냅니다. 예: "🤖 판단 #N 결과 — 매수 2건 · 매도 1건 · 차단 1건". 본문은 6줄까지이고, 넘으면 '외 N건'입니다.
  - 세션 밖에서 생긴 지정가 체결·손절 등은 마지막 건 뒤 1분 동안 새 건이 없으면 묶어서 보냅니다.
  - 주문이 없는 세션은 '판단 완료' 알림을 켰을 때만 보냅니다. 킬 스위치·오류 알림은 지금처럼 바로 갑니다.
- **휴대폰 상단 바는 스크롤해도 높이가 그대로**입니다(D-60 의 '상단 바 접기'를 없앴습니다)
  - 상단 바가 접혔다 펴질 때마다 본문이 100px 가까이 위아래로 움직였습니다. 그래서 스크롤이 '휙휙' 튀었습니다.
  - 이제는 내리면 그림자만 답니다.
- **장 밖에서도 실시간 갱신**
  - 보유 종목 평가금은 웹소켓 연결과 관계없이 늘 10초마다 다시 받습니다. 시간외·데이마켓 체결로 값이 움직이기 때문입니다.
  - 한눈에 보기는 15초마다 다시 받습니다.
  - 주요 지표는 현재가(지수·ETF·환율)를 15초 캐시하고, 일봉(전일 종가·추이선)은 10분 캐시합니다. 예전에는 둘 다 1분 캐시였습니다.
  - 자산 추이도 총자산과 같은 값으로 끝나게 맞췄습니다 → D-68
- **포트폴리오 '전체'**
  - 위 전환이 '전체'면 포트폴리오 화면에 두 시장을 함께 보여 줍니다.
  - 맨 위에 원화 합계를 보여 주고(토스 환율), 보유 종목은 시장별로 나눕니다.
  - 미체결·체결·지난 주문·결정은 한 표에 시장 표시(🇰🇷/🇺🇸)와 함께 시간순으로 보여 줍니다. 미체결 주문 취소는 그 시장 API 로 보냅니다.
- **뉴스 룸**은 섹션마다 기사를 최대 5개만 보여 줍니다(8개에서 줄임). 예전 판도 화면에서는 5개까지만 보입니다.

### D-62 전략 실험실 — 여러 투자 전략을 모의로 동시에, 실거래는 고른 전략 하나 (2026-11-05)
- **전략 카탈로그** (`backend/app/strategies/styles.py`)
  - 전략: 기본 매니저 · 피터 린치(GARP·PEG) · 워런 버핏(해자·ROE·안전마진·장기 집중) · 벤저민 그레이엄(PER·PBR 깊은 가치·넓은 분산) · 모멘텀·추세(시장 방향·주도주·−7~8% 손절)
  - 전략은 매니저 프롬프트의 '판단 원칙' 자리에 들어갑니다. 리스크 한도는 전략과 관계없이 코드가 강제합니다.
  - 미장 전략 글에는 "재무제표 도구가 없으니 기사·가격으로 확인하고 숫자를 지어내지 말라"는 줄이 붙습니다.
  - 새 전략은 STYLES 에 한 항목을 더하면 됩니다.
- **주 계좌 전략**
  - 시장마다 주 계좌(기존 스택)가 따를 전략 하나를 고릅니다(kv `strategy`). 실거래는 이 계좌에서만, 고른 전략 하나로 합니다.
  - 기본 매니저는 지금처럼 설정의 투자 정책 문구를 씁니다.
- **시나리오**
  - 켠 전략마다 자기 모의계좌(같은 시작 금액·비용 규칙·주 계좌 리스크 설정 복사)를 둡니다. 기록 DB(`data/scenarios/{시장}_{전략}.db`, SQLite)와 매니저도 따로입니다.
  - 시세·캘린더·장외 세션 설정·일봉 저장소·LLM 은 주 계좌 스택 것을 같이 씁니다.
  - 휴대폰 알림·유료 구글 검색은 붙이지 않습니다.
  - 시나리오는 언제나 PaperBroker 입니다. PaperBroker 는 모의가 아니면 주문을 거부하고, 시나리오를 실거래로 바꾸는 API 도 없습니다.
- **실행**
  - 주 계좌 판단(장전·정시)이 끝나면, 켠 시나리오가 같은 종류로 차례로 판단합니다. LLM 동시 호출을 늘리지 않으려는 것입니다.
  - 지난 차례가 아직 돌고 있으면 이번 차례는 건너뜁니다. 시나리오 차례는 주 계좌 판단 잠금 밖에서 돌아, 다음 주 계좌 판단을 막지 않습니다.
  - 장중 1분 감시(지정가·장외 체결, 손절/익절)와 하루 정리도 같이 돕니다.
  - 한 시장에 6개까지 켤 수 있습니다. 판단 세션이 시나리오 수만큼 늘어 LLM 사용량도 그만큼 늘어납니다.
- **화면** (⚗️ 전략 실험실, `/lab`, 매니저·분석 묶음 · 휴대폰 더보기)
  - 성과 비교: 주 계좌가 맨 위, 시나리오는 수익률 순입니다. 평가금·보유·투자 비중·체결·판단 수·마지막 판단 요약을 보여 줍니다.
  - 시나리오마다 지금 판단·자세히(보유·최근 판단·최근 주문)·다시 시작(계좌만 처음 금액으로, 기록은 남김)이 있습니다.
  - 주 계좌 전략 고르기(실거래면 경고)와 시나리오 켜기·끄기(전략별 판단 원칙 보기)가 있습니다.
  - API: `GET /api/lab`, `PUT /api/lab/main`, `PUT /api/lab/scenarios`, `GET /api/lab/scenarios/{id}`, `POST …/run`, `POST …/reset` (미장은 `/api/us/lab…`)
- 검증은 가짜 토스·규칙 기반 판단(LLM 없음)으로만 했습니다. 실제 LLM 으로 전략별 판단 품질은 아직 보지 않았습니다.

  - 한 차트에 최대 10페이지(2,000개)까지만 받습니다. 분봉 차트는 20초, 일봉 차트는 5분 캐시합니다.
  - 봉 시각 규칙(명세): 종목 1분봉의 timestamp 는 **봉 종료 시각**, 지표 봉은 **봉 시작 시각**입니다. 일봉은 거래일 현지 자정입니다.
  - 분봉 차트의 가로축은 한국 시각입니다. 미장 종목도 데이·프리·애프터마켓 봉이 그대로 보입니다.
- **지표 차트**: 대시보드·한눈에 보기의 지표 카드를 누르면 아래 시트에 차트가 열립니다.
  - 코스피·코스닥: 분·일 모두 됩니다. 국고채는 분봉이 없어(명세) 일·주·월만 고를 수 있습니다.

  - 원/달러: Open API 에 환율 봉이 없어 차트 대신 안내만 합니다.

- 휴대폰에서 차트 위를 옆으로 밀면 차트가 움직이고 화면 넘기기(D-60)는 하지 않습니다.

### D-66 LLM 요금 장부 — 호출마다 모델·토큰·실제 요금, 공식 기록과 대조, Anthropic 제외 (2026-11-05)
- **바꾼 이유**: 예전 'LLM 비용 예상'(D-41)은 지금 사용량을 상용 모델 단가로 바꿔 본 추정이었습니다. 캐시 적중도 추정(바로 전 호출 입력)이었고, 무료·유료·여러 모델이 한 막대에 섞였습니다. 이제 **호출마다 실제로 쓴 모델·토큰·요금**을 장부에 남기고 그 합계를 그대로 보여 줍니다. '모델별 예상 요금'·'캐시 적용(추정)/캐시 없음' 토글은 없앴습니다.
- **장부** (`llm_usage`, 마이그레이션 0006)
  - 열을 더했습니다: market·strategy(어느 시장·계좌), profile(무료/유료), provider, served_model(응답이 알려 준 실제 모델), upstream, response_id, cache_read_tokens(제공사가 알려 준 캐시 읽기, 모르면 NULL), cache_write_tokens, reasoning_tokens, cost_usd, cost_source, origin.

- **요금 매기기** (`app/agent/costs.py`, 순서대로)
  - reported: 제공사가 응답에 적어 준 요금. OpenRouter 는 응답마다 usage.cost(USD, 캐시·추론 반영)를 줍니다(공식 문서: usage-accounting).
  - free: 자체 서버(무료 묶음 LLM_TEST_*)는 0원.
  - priced: OpenAI·Google 직접 연결은 응답에 요금이 없어 토큰 × 공식 단가로 계산합니다.
    - 입력 = 캐시 읽기(캐시 단가) + 캐시 쓰기(OpenAI GPT-5.6 이후: 입력 단가의 30분 1.25배·12시간 2.5배) + 나머지(기본 단가). OpenAI 의 input_tokens 에는 캐시 읽기·쓰기가 들어 있습니다.
    - 추론 토큰은 출력 단가입니다. OpenAI 는 output_tokens 에 이미 들어 있습니다. Google OpenAI 호환 주소는 completion_tokens 에 생각 토큰이 들어가는지 문서에 없어, total − 입력 − 출력이 남으면 그만큼을 출력 단가로 더합니다.
    - 응답의 service_tier: flex·batch 는 50%, fast·priority 등 별도 표는 단가 모름으로 둡니다. 장문 구간은 호출 1회 입력으로 정합니다.
  - unpriced: 단가표에 없는 모델은 0원으로 치지 않고 '단가 모름'으로 따로 셉니다.
  - estimated: 장부 전 기록은 캐시 적중을 몰라 예전 추정으로 계산합니다(부팅 때 한 번).
- **공식 기록과 맞춰 보기** (`app/agent/billing.py`, `GET /api/llm/costs/official`, 10분 캐시)
  - OpenRouter: 일반 LLM 키로 `GET /api/v1/key` 의 usage_daily·weekly·monthly(UTC)를 장부와 나란히 둡니다. 키 단위라 같은 키를 쓰는 다른 앱 사용분도 들어갑니다. 모델별 활동(`/api/v1/activity`)은 관리용 키가 따로 있어야 해서 쓰지 않습니다.

### D-67 대화에서 자라는 기억 — 되풀이하면 오르고, 한 번이면 빠진다 (2026-11-05)
- 예전 '최근 대화 5개'(D-47)는 날짜와 관계없이 최근 메시지 5개를 그대로 넣어, 한 번 한 말(예: '카카오')이 며칠 뒤까지 끼어들었습니다. 이제 트레이딩 룸에서 꺼낸 **주제**(종목·업종·테마·운용 지시)를 주제별로 모으고(`memory_topics` 테이블, 마이그레이션 0007, 시장마다 따로), 중요도가 기준(0.35) 이상인 주제만 최대 8개, 판단·답장 기억에 넣습니다. 보낸 말을 그대로 넣지는 않습니다.
- 중요도(0~1)는 저장하지 않고 읽을 때 오늘 날짜로 다시 계산합니다(`app/agent/topics.py` `score`). 판단 세션이 없어도 날이 지나면 줄어듭니다.
  - 기본 = 0.4 + 0.6·(1 − e^(−(n−1)/2)) + 연달아 물은 날 보너스(하루당 0.05, 최대 0.15). n = 최근 21일 중 언급한 날 수
  - 마지막 언급 뒤 반감기 1 + 1.5·(n−1)일(최대 10일)로 줄고, 매니저 판단(올림 +0.2 · 유지 0 · 내림 −0.2)을 더합니다
  - 예) 한 번: 그날 0.40(들어감) → 다음 날 0.20(빠짐) / 다음 날 또 물음: 그다음 날 0.52 → 사흘 뒤 빠짐 / 나흘 연달아: 일주일 뒤에도 남음
- 매니저(LLM) 판단: **새 사용자 메시지가 있을 때만** 판단 세션 시작 전에 LLM 을 1번 부릅니다(`AgentRunner.review_topics`). 새 메시지와 지금 주제(통계 포함)를 주고, ① 메시지마다 다룬 주제(있던 key 를 다시 쓰거나 새 이름·종목 코드), ② 주제마다 올림/유지/내림/잊기와 한 줄 이유를 JSON 으로 받습니다.
  - 지어낸 주제를 막으려고 새 주제는 이번 메시지 id 를 근거로 대야만 받고, 종목 코드는 그 시장 목록에 있어야 종목 주제가 됩니다(없으면 이름만).
  - '잊어줘'(forget)는 다시 꺼낼 때까지 중요도 0입니다. 답을 못 읽으면 다음 세션에 다시 하고, 3번 연달아 실패하면 그 메시지들은 건너뜁니다(같은 호출을 계속 반복하지 않게).
  - 비용: 짧은 호출 1번(새 메시지 + 주제 최대 40개). 요금 장부(D-66)에 종류 `memory`(기억 정리)로 남습니다. 규칙 기반 모드는 정리하지 않습니다.
- 메모 화면 '🧠 대화에서 기억하기': 켜기/끄기(kv `memory_settings.topics`, 기본 켬 — 예전 `use_recent_messages` 값은 쓰지 않음), 주제마다 중요도 막대·언급한 날(연속 일수)·마지막 날·매니저 판단과 이유·최근 인용, **늘 기억 / 자동 / 빼기**, 지우기, '지금 정리'(LLM 1번). 에이전트 구조 화면 '매니저의 기억'에도 지금 들어가는 주제가 보입니다.
- API: `GET /api/memory/topics`, `PATCH /api/memory/topics/{id}` `{pin: ""|"pin"|"mute"}`, `DELETE /api/memory/topics/{id}`, `POST /api/memory/topics/review`, `PUT /api/memory/settings` `{topics}` (미장은 `/api/us/...`).
- 처음 켜질 때는 최근 21일 안의 메시지(최대 60개)부터 정리합니다. 60일 동안 안 꺼낸 자동 주제는 지웁니다(고정한 주제는 남김). 확인은 가짜 LLM 응답으로만 했습니다(실제 정리 품질은 배포 후 첫 판단 세션에서 확인).

### D-68 자산 추이 끝 = 총자산 · 장외 세션 자산 기록 (2026-11-05)
- **문제**
  - 미장 총자산은 $10,013인데 자산 추이 끝은 $9,960이었습니다. 국장도 총자산 9,956,690원인데 자산 추이 끝은 9,936,990원(15:30 정규장 마감)이었습니다.
  - 총자산 카드는 실시간 시세(장외 시세 포함)로 10초마다 다시 계산합니다. 자산 추이는 저장된 자산 스냅샷인데, 스냅샷은 정규장 10분마다·마감 뒤 한 번만 쌓였습니다.
  - 그래서 켠 장외 세션(국장 NXT 프리·애프터, 미장 데이·프리·애프터)의 시세 변동·체결이 차트에 없었습니다. 모의 시장가 주문은 접수 때 바로 체결돼 '체결 뒤 기록'도 타지 않았습니다.
- **켠 장외 세션에서도 10분마다 자산 기록**
  - 1분 감시가 정각 10분마다 기록하고, 일봉 갱신·판단 뒤에는 최근 10분 안에 기록이 없을 때만 기록합니다(정규장과 같은 규칙).
  - 장외 세션이 끝난 뒤 몇 분(감시만 하는 구간)에 그 세션 마감 자산을 한 번 남깁니다. 예: 국장 애프터마켓 20:00.
  - 끈 세션은 예전처럼 기록하지 않습니다.
- **화면: 자산 추이 끝에 '지금' 점**
  - 총자산 카드와 같은 값·시각의 점을 차트 끝에 붙입니다. 그래서 스냅샷 사이·장 밖에서도 차트 마지막 값이 위 총자산과 같습니다. 국장·미장 대시보드 모두 같습니다.
  - 스냅샷은 1분마다 다시 받습니다(예전에는 화면을 열 때 한 번).
  - '지금' 점은 10초마다 바뀌므로, 점 수가 그대로면 보던 확대·위치를 지키고 새 스냅샷이 붙을 때만 전체를 맞춥니다.

### D-69 포트폴리오 시각화: 비중 도넛 · 모자이크(트리맵) (2026-11-05)
- **보유 종목 카드에 보기 전환**: 표 · 비중 · 모자이크. 고른 보기는 이 기기에 기억합니다(`portfolio.view`). 시장별 화면과 '전체' 보기의 시장별 카드에 모두 붙습니다.
- **비중(도넛)**
  - 조각 = 종목 평가금액, 현금은 회색 조각으로 따로. 비중은 (평가금액 + 현금) 합계 대비라 보유 종목 표의 비중(평가금액 ÷ 총자산)과 같습니다.
  - 색은 검증된 범주형 8색을 큰 순서대로 씁니다. 종목이 8개를 넘으면 큰 7개만 색을 주고 나머지는 '기타 N종목'(회색)으로 묶습니다. 범례에서 '기타'를 누르면 묶인 종목이 바로 아래에 펼쳐집니다.
  - 범례: 이름 · 티커 · 비중 · 금액 · 수익률(빨강 이익 / 파랑 손실). 조각이나 범례에 올리면(휴대폰은 누르면) 가운데가 그 종목의 비중·금액·수익률로 바뀝니다.
- **모자이크(트리맵)**
  - 넓이 = 비중, 색 = 수익률(한국 관례: 이익 빨강 · 손실 파랑, ±0.5% 안은 회색). 경계는 ±0.5 · 2 · 5% 세 단계.
  - 배치는 squarified treemap(`frontend/src/utils/treemap.ts`): 칸이 정사각형에 가깝고, 넓이가 값에 비례하며 겹치지 않습니다(단위 테스트).
  - 칸을 누르면 넓은 화면은 종목 화면, 휴대폰은 빠른 보기 시트. 작은 칸은 글자를 숨기고 툴팁·스크린리더 이름만 둡니다. 현금은 점선 회색 칸. 종목이 12개를 넘으면 상자를 더 높게 그립니다.
- **전체 보기(국장 + 미장)**: '🧭 전체 보유 비중' 카드. 미장은 토스 원/달러 환율로 원화로 바꿔 한 그림에 넣고 국기를 붙입니다. 합계 금액은 위 '전체 자산' 카드에만 두고 가운데에는 종목 수·현금 비중만 씁니다(받는 시각이 달라 몇 원 어긋나 보이지 않게).
- 차트 라이브러리 없이 SVG·HTML 만 씁니다(처음 받는 조각이 커지지 않음). 밝은·어두운 화면 색 단계를 따로 둡니다(`PortfolioViz.css`).

### D-70 재배포하면 열려 있는 화면이 스스로 새로고침 (2026-11-05)
- **무엇을 보나**
  - 화면 배포: `/index.html` 을 다시 받아(no-cache, 안 바뀌면 304) 입구 스크립트 이름(`/assets/index-<해시>.js`)이 지금 화면의 것과 다르면 새 화면이 배포된 것입니다.
  - 서버 배포: `/api/health` 의 `boot`(서버 프로세스가 뜰 때마다 새로 정하는 값)가 처음 본 값과 달라지면 서버가 다시 뜬 것입니다. 로그인 없이 부르는 주소라 로그인 화면에서도 됩니다.
  - 30초마다(화면이 숨어 있으면 2분마다), 그리고 다시 보이거나 네트워크가 돌아오면 바로 확인합니다. 첫 확인은 뜬 지 5초 뒤입니다.
- **언제 새로고침하나**
  - 화면이 숨어 있으면 바로, 보이고 있으면 '🔄 새 버전이 배포돼 화면을 새로고침해요' 안내를 1.5초 띄운 뒤.
  - 글자가 든 입력 칸에 초점이 있거나 창(dialog)이 열려 있으면 5초마다 다시 보며 끝날 때까지 기다립니다.
  - 받지 못한 값(서버가 다시 뜨는 중 502, 오프라인)은 바뀐 것으로 보지 않습니다.
  - 1분 안에 이 이유로 이미 새로고침했으면 다시 하지 않습니다(sessionStorage — 캐시 등으로 계속 다르게 보일 때 무한 새로고침 방지). 저장소를 못 쓰면 하지 않습니다.
- 빌드한 화면(입구가 `/assets/`)에서만 켜집니다. 개발 서버·테스트에서는 꺼져 있습니다. 서비스 워커는 화면 파일을 캐시하지 않아(`public/sw.js`) 새로고침하면 새 조각을 받습니다.
- 이 기능이 들어가기 전에 열어 둔 화면은 감시 코드가 없으므로 이번 배포 한 번은 직접 새로고침해야 합니다.
- 코드: `frontend/src/version.ts`(감시), `backend/app/api/routes/auth.py`(`BOOT_ID`).

### D-71 제공사 키를 함께 등록하고 화면에서 제공사·모델 전환, OpenRouter 는 등록한 모델만 (2026-11-06)
- **키**: `.env` 에 `OPENAI_API_KEY`·`OPENROUTER_API_KEY` 를 함께 넣어 둔다. `LLM_*` 는 기본 연결(처음 쓰는 모델)로 그대로 두고, 제공사 자리가 비었으면 `LLM_*` 키가 그 제공사일 때 그 키를 쓴다. 키 값은 화면·API 로 내보내지 않고 '키 있음/없음'만.
- **유료 모델 = (제공사, 모델)**: 고른 값은 `llm_paid_model` {model, provider} 에 남는다. 다른 제공사를 고르면 그 제공사 공식 주소·키·호출 방식(OpenAI = Responses, OpenRouter = Chat Completions)으로 LLM 을 새로 만든다. 쓸 수 없게 되면(키를 뺌·등록 해제·목록에서 사라짐) `LLM_*` 로 돌아간다. 예전 저장값(모델만)은 이름으로 제공사를 짐작한다.
- **OpenRouter 는 등록한 모델만**: 수백 개 전체 목록 대신, 설정 화면에서 검색(목록 API 캐시, 도구 호출 지원·Anthropic 제외)해 '등록'한 모델(최대 30개)만 유료 모델 목록에 나온다(`openrouter_models`). `LLM_*` 가 OpenRouter 면 그 모델은 늘 등록돼 있다. 지금 쓰는 모델·.env 모델은 등록을 뺄 수 없다.
- **API**: `PUT /api/llm/model` {model, provider}, `GET /api/llm/openrouter/catalog?q=`, `POST /api/llm/openrouter/registered` {id}, `DELETE /api/llm/openrouter/registered?id=`, `POST /api/llm/openrouter/models/refresh`(OpenRouter 키가 있으면).
- 요금 장부·공식 대조는 그대로 — 제공사는 호출 주소로 정하고, OpenRouter 대조에는 `OPENROUTER_API_KEY` 도 쓴다. 관리용(Management) 키는 쓰지 않는다(호출 불가, 일반 키로 키 사용액 조회).
- 테스트는 셸 환경의 `OPENAI_API_KEY` 등을 읽지 않도록 막는다(`tests/conftest.py`).

### D-72 국장·미장 DB 하나로(Postgres `us` 스키마) + 주요 지표 하루 종가 기록 (2026-11-06)
- **DB 하나로**: 국장 `DATABASE_URL` 이 Postgres 면 미장은 같은 데이터베이스의 `us` 스키마를 쓴다(주소에 `options=-csearch_path=us`). 테이블 구조·코드·Alembic 마이그레이션은 그대로 — 모든 테이블에 시장 열을 붙이는 대신 스키마로 나눠 위험을 줄였다. `US_DATABASE_URL` 로 따로 지정하면 그것을 쓴다.
- **옮기기**: 기동할 때 예전 미장 SQLite(`{DATA_DIR}/us_market.db`)가 있고 `us` 스키마가 비어 있으면(모의계좌·판단·자산 기록 없음) 모든 테이블을 외래키 순서로 그대로 옮기고(id 유지, Postgres 시퀀스 맞춤) 파일을 `us_market.db.migrated` 로 바꿔 둔다(되돌리기용, 지우지 않음). 옮길 곳에 행이 있으면 옮기지 않는다. 운영 DB 사본으로 리허설해 13개 테이블 행 수·모의계좌 현금·보유 종목이 같음을 확인했다(`backend/app/db/unify.py`).
- 전략 실험실 시나리오 DB 는 아직 SQLite 파일 그대로다(요금 기록은 D-66 에서 이미 국장 장부로 모았다).
- **주요 지표 하루 종가**(`benchmark_daily`, 국장 DB): 코스피·코스닥·국고채 10년(토스 지표 일봉, 한국 날짜), QQQ·SPY·DIA(토스 종목 일봉, 뉴욕 날짜), 원/달러(봉 API 가 없어 16:10 현재 환율). 매일 07:10(미장 마감 뒤)·16:10(국장 마감 뒤) 최근 10개 일봉으로 덮어써 마감값을 맞추고, 처음에는 200일을 채운다. 분 단위는 남기지 않는다(분석은 일 단위). 조회: `GET /api/market/benchmarks?days=`.
- 다우존스는 토스에 지수가 없어 DIA ETF 를 지표 띠·차트에 더했다(나스닥 = QQQ, S&P = SPY 와 같은 방식).
- 자산은 국장·미장 각 스키마의 `equity_snapshots`(장중·장외 10분, 마감 때)에 있어, 날짜별 마지막 값을 지수 종가와 맞춰 보면 된다.

### D-73 Qwen Cloud 를 유료 LLM 제공사로 (2026-11-09)
- **연결**: OpenAI 호환 Chat Completions, 주소는 지역마다 `https://{region}.maas.qwencloudapi.com/compatible-mode/v1` (싱가포르 `ap-southeast-1` 기본, us-east-1·eu-central-1·ap-northeast-1·cn-hongkong·cn-beijing). 키는 지역마다 따로라 `.env` 에 `QWEN_API_KEY` 와 키를 만든 지역 `QWEN_REGION` 을 넣는다. 출처: docs.qwencloud.com getting-started/regions, administration/api-keys.
- **모델 고르기**: D-71 의 (제공사, 모델) 고르기에 Qwen Cloud 묶음을 더했다. 공식 문서에 모델 목록 API 가 없어 가격표 모델만: qwen3.8-max · qwen3.7-max · qwen3.7-plus · qwen3.8-flash · qwen3.7-flash (일반 텍스트 모델은 모두 도구 호출 지원).
- **도구 강제**: Qwen 은 생각 모드에서 특정 도구 강제(tool_choice 함수 지정)를 받지 않는다. 판단 마지막의 '결정 제출' 강제 호출에만 `enable_thinking: false` 를 보낸다(그 밖의 호출은 모델 기본값). 출처: text-generation/function-calling, api-reference/chat/openai-chat.
- **요금**: 국제(싱가포르) 정가를 단가표에 넣었다(USD/100만 토큰, 생각 출력도 같은 값). 입력 구간이 셋인 모델을 위해 단가표에 구간(tiers)을 더했다(qwen3.7-flash: 3.2만·25.6만 초과). 캐시 적중은 모델 페이지(qwencloud.com/models/<id>)의 자동 캐시 단가로 센다(2026-11-09 보완: 3.8-flash $0.016, 3.8-max $0.25, 3.7-max $0.5, 3.7-plus $0.064(한시 20% 할인가), 3.7-flash $0.006 — 3.8 계열은 입력의 20% 가 아니고, 표에 없는 3.7 구간은 문서 규칙대로 20%). 공식 청구 조회: API 키로 부르는 사용량·요금 API 는 문서에 없다. qwencloud CLI 의 `usage` 명령은 브라우저 로그인(OAuth 기기 인증)이 필요해 서버 자동 대조에는 쓰지 않는다. 응답 usage 의 `prompt_tokens_details.cached_tokens`, `completion_tokens_details.reasoning_tokens`(출력에 포함)를 장부에 남긴다.
- **공식 대조**: 키로 조회하는 사용량·요금 API 가 문서에 없어 '공식 조회 없음'(Google 과 같다).
