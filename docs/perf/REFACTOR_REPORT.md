## 한 줄 요약
화면은 **덜 받고(첫 로딩 −84%), 덜 그리고(대기 중 다시 그리기 −98%), 덜 묻고(대기 중 API −73%)**, 서버는 **SQL 을 1/26 로(목록 API 302→1회), 장 밖에서는 아무것도 하지 않게(토스 호출 0)** 바꿨다. 느린 휴대폰 회선의 첫 화면은 6.5초 → 3.9초. 기능·API 형식은 그대로이고 테스트는 모두 통과(서버 323 · 화면 266 · e2e 6).

## 측정 방법
- 같은 스크립트를 리팩토링 전(`before`)·후(`after`)에 같은 방식으로 돌렸다. 실서버에는 조회(GET)만 보냈다.
- 서버: ① 실서버 API 지연(엔드포인트마다 15회, p50/p95) ② **같은 시드 데이터**(채팅 2,000·세션 300·주문/체결 1,000·감사 5,000·자산 2,000·일봉 50종목×200일)로 만든 임시 DB 에서 요청당 SQL 수·시간·바이트 — 데이터가 쌓였을 때의 비용을 재현 가능하게 본다 ③ 실서버 DB 표·인덱스 ④ 코드 지표.
- 화면: 실제 배포 화면(nginx)을 Playwright 로 — 데스크톱 1440×900, 휴대폰 375×812(CPU 4배 느리게), 휴대폰+Fast 3G. 13개 화면 × 3회 중앙값, 60초 대기 부하, 스크롤·시장 전환, 컴포넌트 렌더 수.
- 한계: 전(22:57~23:45)·후(00:00~02:10) 측정 시각이 달라 미장 장중 여부가 다르다(후 측정 때 미장 개장). 실서버 DB 는 약 2.5일치라 실서버 지연은 고정 비용 위주이고, 데이터가 늘 때의 차이는 ②에서 본다. 헤드리스 브라우저는 실제 폰보다 프레임이 후하다.

| 지표 | 전 | 후 | 비고 |

구조적으로 바뀐 것
- **이름 조회 N+1 → 메모리 맵 + 일괄 조회**: 목록 API 와 판단 세션의 SQL 대부분이 사라졌다.
- **설정(kv)·종목 이름·매매 원장·비용 계산 캐시**: 쓰기 즉시 갱신(write-through), 시장(DB)별로 따로. 킬 스위치·리스크 설정은 저장 즉시 반영됨을 테스트로 고정.
- **장 시간 게이트**: 1분 점검·10분 갱신·자산 스냅샷이 장 운영 시간 근처에만 돈다(미장은 한국 자정을 넘기는 세션 기준).
- **화면 실시간 상태를 작은 저장소 + 선택 구독(useSyncExternalStore)으로**: 메시지 하나에 머리말·메뉴·모든 화면이 다시 그려지던 구조를 끊었다.
- **실시간 연결 중에는 느린 폴링**(5초 → 30초), 끊기면 원래대로.
- **nginx gzip + 해시 파일 1년 캐시**, 없는 조각은 404(옛 화면이 지난 배포 조각을 찾으면 한 번 새로고침).

## 7. 나빠졌거나 그대로인 것 (솔직하게)
- **휴대폰 CPU×4, 빠른 회선의 첫 화면 시간**: 중앙값 319 → 328ms(+3%), 최대 화면 415 → 431ms(+4%). 화면을 조각으로 나누면서 요청이 한 번 늘었다. 측정 오차 범위에 가깝고, 느린 회선에서는 −40% 로 크게 좋아졌다. 처음에는 +14%(최대 +49%)였는데, 미리 받은 화면을 React.lazy 가 한 번 더 멈추는 문제를 고쳐 줄였다.
- **전체 JS 합계(gzip)**: 193 → 235KB(+22%). 처음에 받는 양은 절반이 됐지만, 밤새 추가한 화면(미장·메모 카드·판단 일정·설정 분리·팔레트·시트)과 조각 나눔의 오버헤드로 전부 합친 양은 늘었다. 쓰지 않는 화면은 받지 않는다.
- **코드 줄 수·CSS**: 화면 9,668 → 13,321줄, CSS 4,667 → 5,939줄. 같은 밤에 들어간 새 기능(미장 화면·메모 카드·판단 일정·설정 분리·앱 UI)이 대부분이라 리팩토링만의 효과로 읽으면 안 된다. `as` 형 변환 25 → 37 은 다음에 줄일 거리.
- **전체 화면 대기 중 메인 스레드 작업**: 409 → 474ms/분(+16%). 숫자 변화 애니메이션·상대 시각 갱신 비용으로 보인다(스크립트 실행 시간은 −2%).
- **판단 세션의 LLM 입력 크기·토스 호출 수**: 그대로(판단 품질에 영향을 줄 수 있어 이번 범위에서 뺌).
- **서버 응답의 큰 목록**(`/events`, `/reports`)은 gzip 으로 전송량만 줄였고, 응답 형식은 그대로 두었다(화면 계약 유지).
